# Plan: playable Mastermind UI (welcome → classic game), i18n en/fi/sv, saved games

## Context

The game rules in `src/game/` are done (`newGame` → `startGame` → `makeGuess`, immutable state),
but the app still renders "Hello, world!". This change adds the UI to play:

- When the app loads, show a welcome screen with a short rules summary and a "Play classic Mastermind" button.
- The welcome screen is the view for the `setup` state. Game configuration will be added there later,
  so it starts the game by sending a `GameConfig` (only `CLASSIC` for now).
- Play happens on an abstract board: rows of round pegs and a small grid of feedback dots.
- All UI text is translated into English, Finnish and Swedish with `@aurelia/i18n`.
- A game in progress and the chosen language survive a page reload (localStorage).

Decisions you made: en + fi + sv; `@aurelia/i18n`; guess input with an active slot that moves to
the next empty slot automatically, where tapping a slot makes it active; persistence in localStorage.

## Architecture: layers with one job each, so the UI can be redesigned later

The goal is that a visual redesign replaces templates and CSS, and leaves rules, state and input
logic alone. Each layer depends only on the layers above it in this table:

| Layer | Where | Job | Aurelia? |
|---|---|---|---|
| Rules | `src/game/` | Scoring, transitions, save/restore | no |
| Session | `src/session/` | Holds the current `GameState`, persists it, exposes commands (`start`, `guess`, `playAgain`, `quit`) | no |
| Input and view model | `src/play/` | `GuessDraft` (input row state), `keyToCommand` (keyboard mapping), `buildBoard(state, draft)` → `BoardView` (plain data describing what to show) | no |
| Containers | `src/components/welcome-screen`, `src/components/game-board` | Connect the session and the input layer to presentational components; the only components that use `resolve(GameSession)` | yes |
| Presentational | `src/components/{guess-row,code-peg,feedback-pegs,color-palette,result-panel,language-picker}` | Render bindables and raise events through callback bindables; no DI, no game logic | yes |
| Theme | `src/styles.css` | Design tokens (colors, spacing, peg size); components use only tokens | — |

Rules this layering follows:
- Templates contain no game logic, only bindings to `BoardView` fields and command calls. Values such
  as "can submit", "guesses left", "row is current" and "show the result" are computed in
  `buildBoard` and are unit tested.
- Presentational components only take data in (`@bindable`) and send intents out
  (`select.bind="i => …"`, `pick.bind="c => …"`). This lets them be rearranged or replaced (for
  example a horizontal board or a different peg style) without touching the containers.
- Color identity (`Color`) is mapped to visuals in one place: the `--color-<name>` tokens and the
  `peg--<name>` class. Translation keys describe meaning, not layout (`board.feedback`, not
  `sidebar.text`).
- Adding a game configuration later only touches the setup layer: a config form in
  `welcome-screen` (or its own component) that builds a `GameConfig` for `session.start(config)`.
  `buildBoard` already takes `pegs`, `colors` and `maxGuesses` from `state.config`.

```
main.ts ── registers I18nConfiguration (resources bundled, language from detectLanguage())
my-app ── header (title + language-picker), shows one container based on session.state.status
  ├─ setup             → <welcome-screen>  ── session.start(CLASSIC)
  └─ playing/won/lost  → <game-board>      ── buildBoard(session.state, draft) → BoardView
                                              → <guess-row>×n, <color-palette>, <result-panel>
GameSession (DI singleton, no Aurelia imports) ── owns GameState, saves it on every change
game/save.ts (pure) ── serializeGame / restoreGame (validates by replaying through makeGuess)
```

Views are chosen from state, not with `@aurelia/router`: the persisted state is the source of
truth, so URLs would only fall out of sync with it. The router dependency stays unused, as it is now.

## Files

### Game layer: `src/game/save.ts` (+ `save.test.ts`, exported from `src/game/index.ts`)
- `interface SavedGame { version: 1; config: GameConfig; secret: Code; guesses: Code[] }`.
  Only inputs are stored; feedback and status are derived.
- `serializeGame(state: StartedState): SavedGame`.
- `restoreGame(data: unknown): StartedState | undefined`: checks the shape (version, arrays, colors in
  `ALL_COLORS`), runs `validateConfig`, checks the secret with `isValidGuess`, builds a `playing` state
  and replays every guess through `makeGuess`. Returns `undefined` for anything invalid or
  inconsistent, such as guesses after a win. Reuses `validateConfig` (`config.ts`), `isValidGuess`
  (`score.ts`) and `makeGuess` (`game.ts`).
- Tests: round trip for playing, won and lost games; rejects garbage, a wrong version, an invalid
  config, an invalid secret or guess, extra guesses after the game ended, and a non-object.

### Session: `src/session/game-session.ts` (+ `game-session.test.ts`), `src/session/storage.ts`
- `storage.ts`: `IStorage` (`get(key)`, `set(key, value)`, `remove(key)`) with a localStorage
  implementation that wraps each call in try/catch, because storage can be unavailable or full.
  Keys: `mastermind:game`, `mastermind:lang`.
- `GameSession`: `state: GameState` (restored at construction, otherwise `newGame()`) and the methods
  `start(config = CLASSIC)`, `guess(code)`, `playAgain()` (a new game with the same config),
  `quit()` (back to `setup`). Each method saves the state, or removes the saved game when it returns
  to setup. Components get it with `resolve(GameSession)`, and storage is injectable so tests can
  pass a fake. It has no Aurelia imports, so it can be tested in node.
- Tests use a fake storage: start/guess/quit save and clear correctly, a reload continues the game,
  and corrupt storage gives a new game.

### i18n: `src/i18n/`
- Add the dependency `@aurelia/i18n` pinned exactly at `2.0.0-rc.2`. It brings `i18next` with it;
  don't add `i18next` directly unless we import it.
- `en.json`, `fi.json`, `sv.json`: bundled with `import` (`resolveJsonModule` is already on), so no
  HTTP backend is needed and the base path doesn't matter. Plurals use the i18next `_one` / `_other`
  suffixes with `count`.
- `index.ts`: `LANGUAGES = ['en', 'fi', 'sv'] as const`, `resources`, and a pure
  `detectLanguage(stored, navigatorLanguages)` that tries the stored language, then the browser
  languages by prefix (`fi-FI` → `fi`), then `en`.
- `locales.test.ts`: fi and sv have exactly the same key set as en, including every `colors.<c>`
  in `ALL_COLORS`, and no value is empty. Also tests `detectLanguage`.
- Key groups: `app.title`, `language.label`, `welcome.*` (title, intro, rules, playClassic),
  `game.*` (guessesLeft_one/_other, submit, clear, quit, confirmQuit, won_one/_other, lost,
  secret, playAgain, mainMenu), `board.*` (row "Guess {{n}}", slot "Position {{n}}: {{color}}",
  emptySlot, feedback "{{exact}} right place, {{misplaced}} wrong place"), `colors.*` (all 10).
- Templates use `t="key"`, `t.bind`, `t-params.bind` and `| t`. `main.ts` registers
  `I18nConfiguration.customize(o => { o.initOptions = { resources, lng, fallbackLng: 'en' } })`.
- `language-picker` component: a `<select>` with each language's own name (English, Suomi, Svenska,
  which are not translated). On change it calls `I18N.setLocale`, saves to `mastermind:lang` and
  sets `document.documentElement.lang` and `document.title`. `index.html` gets `<html lang="en">`.

### Input and view model: `src/play/` (no Aurelia imports, each file has a `.test.ts`)
- `guess-draft.ts`: a plain class for the input row: `slots: (Color | null)[]`, `active`,
  `pick(color)` (fills the active slot, then moves to the next empty one), `select(i)`, `clear(i)`,
  `backspace()`, `move(±1)`, `isComplete`, `code`, `reset()`. Not saved, which is fine because it's
  one row.
- `keyboard.ts`: `keyToCommand(key, colorCount)` returns a `Command`
  (`{ type: 'pick', index } | 'move' | 'backspace' | 'clear' | 'submit'`) or `undefined`, so the
  key bindings are data that can be tested.
- `board.ts`: `buildBoard(state: StartedState, draft: GuessDraft): BoardView`. The view contains
  `rows: RowView[]` (`kind: 'past' | 'current' | 'empty'`, `pegs: (Color | null)[]`,
  `activeSlot?`, `feedback?`), `palette`, `guessesLeft`, `canSubmit` (from `isValidGuess`), and
  `result?: { outcome: 'won' | 'lost', guessCount, secret }`. The secret appears only when the game
  is over.

### Components: `src/components/` (convention-based, each `.ts` + `.html` (+ `.css`), imported via `<import>`)
Containers: `welcome-screen` and `game-board`. All the other components are presentational, as
described in the Architecture section.
- `welcome-screen`: welcome title, intro, a short rules list (4 pegs, 6 colors, 10 guesses, what
  black and white dots mean), and the button **Play classic Mastermind** → `session.start(CLASSIC)`.
  Leave room for a future config form that builds the `GameConfig` passed to `start`.
- `game-board` (container): owns a `GuessDraft`, exposes `board` as a getter that calls
  `buildBoard(session.state, draft)`, and has one `run(command)` method that applies a `Command` to
  the draft or the session. Its template lays out the following and does nothing else:
  - `guess-row` for each `board.rows`, a "N guesses left" line, `color-palette`, and the Clear and
    Submit buttons (Submit disabled when `!board.canSubmit`)
  - `result-panel` when `board.result` is set
  - a quit button during play that asks for confirmation (translated `window.confirm`)
  - keyboard: a `window` keydown listener, added in `attached()` and removed in `detaching()`,
    that calls `run(keyToCommand(...))`. `1`–`n` pick a color, ←/→ move the active slot,
    Backspace clears the previous slot, Delete clears the active one, and Enter submits.
- `guess-row`: takes a `RowView` and its index and renders `code-peg`s and `feedback-pegs`.
  Tapping a slot in the current row calls `select(i)`.
- `result-panel`: takes `result` and shows "Solved in N guesses" or "Out of guesses", the revealed
  secret, and **Play again** / **Main menu** buttons wired to the `playAgain` and `mainMenu`
  callbacks.
- `code-peg`: a round peg for one color, or an empty slot. CSS class `peg--<color>`, plus an
  `aria-label` with the translated color name.
- `feedback-pegs`: a 2×2 grid (the size follows `pegs`) of filled dark dots (right place), hollow
  light dots (wrong place) and blanks, with a translated `aria-label`.
- `color-palette`: buttons for `config.colors` with a small number hint for the key and the
  translated color name as the accessible name.
- `language-picker`: see the i18n section.

### App shell and styles
- `my-app.ts/html/css`: a header with the translated title and `language-picker`, and `<main>` with
  `if.bind` on the status: `welcome-screen` for setup, `game-board` otherwise.
- `src/styles.css` (imported in `main.ts`): theme variables (light and dark through
  `prefers-color-scheme`), one CSS variable for each of the 10 colors in `ALL_COLORS`
  (`--color-red` …), a mobile-first single column with a max width of about 28rem, and visible
  focus rings. The white and black pegs get an outline so they stay visible on both themes.
- Remove the "Hello, world!" template.

3. `GameSession`, storage, and `welcome-screen` wired into `my-app`.

## Verification
- `npm run check` (lint, typecheck, unit tests including save, session, draft and locale parity, build).
- `npm start` (or the `/run` skill), then check by hand at http://localhost:9000:
  - The welcome screen appears, and Play starts a 4×6×10 game.
  - Fill slots by clicking and with the keyboard; change a middle slot; submit; the feedback dots are right.
  - Reload during a game: the game continues. Win and lose (the lose test can use devtools to read
    the secret from localStorage). Play again and Main menu work.
  - Switch to Suomi and Svenska: all text changes, including color names, plurals, `<html lang>`
    and the title, and the choice survives a reload.
  - Corrupt `mastermind:game` in devtools, then reload: the app falls back to the welcome screen.
  - Narrow mobile width and dark mode look right.
- `npm run build && npx vite preview --base /mastermind/` to check that it works under the base path.
- Run the `reviewer` agent on the diff before the final commit.

## Outcome

### Planning

Before planning, the user decided four things:
- the languages: English, Finnish and Swedish
- `@aurelia/i18n` for translations
- guess input with an active slot
- saved games in localStorage

The plan was then restructured into layers, so that a redesign changes only templates and CSS. It
was approved at 09:02 EET.

### As planned

The six steps were done in order, each committed with `/commit`:
1. Saved games.
2. Translations and the language picker.
3. The session and the welcome screen.
4. The `src/play/` layer.
5. The board.
6. The CLAUDE.md docs.

The layered architecture was kept as designed. The PR ended with 103 unit tests.

### Changes from the plan

- **Wrong branch:** step 1 was first committed on the previous PR's branch. At the user's request,
  it was moved to a new branch `add-game-ui` from the latest `main`, and the old branch was reset.
- **Browser testing instead of checking by hand:** no browser was available in WSL.
  - The user chose to install Playwright and its Chromium outside the project, so `package.json`
    stayed unchanged.
  - The user installed Chromium's system libraries with `sudo`.
  - Each step was then checked by a Playwright script in the session's scratchpad. By the end the
    script had 33 checks, and it also ran against the PR preview and production.
  - The script wasn't committed.
- **Storage helper earlier:** it came in step 2 instead of step 3, because the language picker
  needed it. Its interface is called `KeyValueStore`, not `IStorage`.
- **A `play` commit scope:** step 4 was first committed without a scope. The user asked for one,
  so the commit was amended and `play` was added to `/commit`.
- **Observed getters must not mutate (AUR0227):** the board first rendered empty. `buildBoard`
  pushed onto arrays mapped from the game state, which Aurelia counts as a side effect in an
  observed getter. It now builds every array new.
- **Kebab-case CSS classes:** `peg-<color>`, not `peg--<color>`, to match the Stylelint rule.
- **Feedback dots differ by shape:** in dark mode the dark "right place" dot looked like a white
  ring. The dots became a filled dot for right place and a ring for wrong place, which reads the
  same in both themes and without color vision. The rules text changed to match, and the user was
  asked to confirm the design.
- **A narrower palette**, so it fits at 360px.
- **The Guess button uses `aria-disabled`** instead of `disabled`, so it keeps focus after a
  submit. Enter submits even when a palette or slot button has focus.
- **Reviewer findings:** the `reviewer` agent ran before the final commit. The first three findings
  were reproduced in Chromium before fixing:
  1. A half-filled row survived Quit and came back in the next game, because `if`/`else` reuse
     the cached board component. The row is now created in `binding()`.
  2. Typing into a focused slot dropped focus, because rows were rebuilt. Rows and slots now
     repeat by index.
  3. Submitting lost focus. Guess keeps focus, Enter on a slot moves to the next row, and the
     result heading takes focus.
  4. A saved game with a huge config froze the app. Configs are now capped at 10 pegs and 20
     guesses; the limits were chosen by Claude and left for the user to adjust.
  5. Smaller fixes: key hints come from `buildBoard`, `GuessDraft` rejects sizes below 1, and empty
     rows are hidden from screen readers.
  6. CLAUDE.md gaps were corrected.
- **The page title isn't translated:** the title is "Mastermind" in every language, so the language
  picker doesn't set `document.title`.
- **Number keys** reach only the first nine palette colors. That covers the classic six.
- **Merging:** the user asked whether Claude should merge. The answer: merge yourself, after
  reviewing, because merging deploys to production and records the approval. The user merged it.

- PR #5 also deleted the stale `add-claude-workflow` branch and removed the unused
  `@aurelia/router`, which this plan said would "stay unused".
- Game configuration in the setup view is still to be built.
